The `bramburn/CloudCompare` fork now has a docs site, published to
GitHub Pages at
[`bramburn.github.io/CloudCompare`](https://bramburn.github.io/CloudCompare/).

{/* truncate */}

## What's here

- A build cookbook for the local toolchain (CMake 4.3.0, Qt 6.8.3, MSVC
  14.44, Ninja 1.13.2) — the same wrapper scripts at
  `C:\dev\tools\cc-configure.cmd` and `cc-build.cmd` that the fork's
  GitHub Actions matrix uses.
- A full inventory of the **18 self-contained plugins** enabled in this
  fork, with one-line descriptions of what each does and where it
  shows up in the menu.
- A priority list of the **20+ disabled plugins**, their external
  dependencies, and the vcpkg recipe to enable each one.
- A plugin authoring cookbook — copy `plugins/example/ExamplePlugin`,
  rename, wire to the build, ship.
- An architecture map — `CCCoreLib`, `qCC_db`, `qCC_io`,
  `qCC_glWindow`, `CCPluginAPI`, and how they fit together. The
  "if you only have time to read three files" list.
- The full AGENTS.md narrative, broken out into topical pages.

## What's not here

The upstream Wiki and the Doxygen-generated `doc/` HTML are still the
canonical sources for the API reference, the `ccCommandLineParser`
contract, and the per-plugin command-line flags. This site is the
**fork-specific** layer on top: the local toolchain pins, the local
plugin set, the fork's CI workflows, and the vcpkg recipes to extend
the local set.

## How it deploys

The site is built with [Docusaurus 3](https://docusaurus.io/) and
deployed by `.github/workflows/deploy-docs.yml` to the `gh-pages`
branch on every push to `master`. The build is ~1-2 minutes on the
GitHub-hosted runners; `npm ci` is the slow step (~30&nbsp;s with a
warm cache).

To preview locally:

```bash
cd website
npm install
npm start          # http://localhost:3000/CloudCompare/
```
