# AGENTS-ui.md — UI patterns

CloudCompare's GUI is a single-file `QMainWindow` (`qCC/mainwindow.h/.cpp`, ~12,000 lines) that hosts:

- A central **MDI area** for multiple 3D viewports.
- A left dock with the **db-tree** (entities loaded in memory).
- A right area for **overlay dialogs** (clipping box, segmentation, transformation, section extraction, …).
- A bottom dock with the **console** (`ccConsole`).
- Menus + toolbars (some built-in, some added dynamically by plugins).
- A **plugin UI manager** (`qCC/pluginManager/ccPluginUIManager.{h,cpp}`) that owns the plugin menu, plugin toolbar, and GL filter toolbar.

This file documents the conventions a plugin (or a `qCC/` edit) must follow to integrate cleanly.

For the bigger picture (where files live, what's a plugin), see [`AGENTS-architecture.md`](AGENTS-architecture.md). For the plugin recipe, see [`AGENTS-plugin-dev.md`](AGENTS-plugin-dev.md).

## 1. Directory layout inside `qCC/`

```
qCC/
├── CMakeLists.txt                # builds the CloudCompare executable
├── main.cpp                      # main(), CLI vs GUI dispatch
├── mainwindow.h / .cpp           # the QMainWindow; doActionXxx() slots
├── ccApplication.h / .cpp        # the QApplication subclass
├── ccConsole.h / .cpp            # the in-app console widget
├── ccCommandLineParser.{h,cpp}   # CLI parser
├── ccCommandLineCommands.{h,cpp} # CLI verb implementations
├── ccEntityAction.{h,cpp}        # right-click context-menu helpers
├── ccRecentFiles.{h,cpp}         # recent files menu state
├── ccReservedIDs.h               # reserved ccHObject unique IDs
├── ccUtils.{h,cpp}               # misc helpers
├── ccTranslationManager.{h,cpp}  # translations
├── cc*PickingGenericInterface.*  # picking helpers
├── cc*Dlg.{h,cpp}                # one per "built-in" dialog (50+ of them)
├── db_tree/
│   ├── ccDBRoot.{h,cpp}                    # the db-tree root (a ccHObject)
│   ├── ccPropertiesTreeDelegate.{h,cpp}    # right-pane entity properties
│   ├── sfEditDlg.{h,cpp}                   # scalar-field editor
│   └── matrixDisplayDlg.{h,cpp}            # 4x4 transform matrix display
├── pluginManager/
│   ├── ccPluginUIManager.{h,cpp}           # the dynamic menu/toolbar builder
│   ├── ccPluginInfoDlg.{h,cpp}             # Help → About → Plugins
│   ├── pluginManager.qrc
│   └── ui/
├── ui_templates/
│   └── *.ui                                # Qt Designer files (one per cc*Dlg)
├── images/
│   └── icon/                               # app + button icons
├── Mac/                                    # macOS bundle (Info.plist)
├── bin_other/                              # misc platform-specific bits
└── TODO.txt                                # notes (read occasionally)
```

Rule of thumb:
- A **dialog class** is `qCC/cc*Dlg.{h,cpp}` and its layout is `qCC/ui_templates/*Dlg.ui`.
- A **tool** (something that grabs the cursor for picking) is `qCC/cc*Tool.{h,cpp}`; it usually inherits `ccOverlayDialog` and lives in the MDI overlay area.
- A **panel** (passive display) goes into the db-tree's right pane via `ccPropertiesTreeDelegate` or is a separate dock.

## 2. The `.ui` files

- Authored in **Qt Designer** (or by hand in XML).
- Located in `qCC/ui_templates/`.
- Wrapped via `qt6_wrap_ui()` in `qCC/CMakeLists.txt` (a `file(GLOB ui_list ui_templates/*.ui)`).
- Loaded at runtime via `Ui::MainWindow` (auto-generated by `uic`) for the main window, or by `setupUi()` in each dialog's constructor.
- Plugin `.ui` files live in `plugins/<TYPE>/<NAME>/ui/` and are picked up by `AUTOUIC_SEARCH_PATHS` (set automatically by `AddPlugin`).

**Naming:** `cc*Dlg.ui` (camel-case, `Dlg` suffix). E.g. `ccFilterByValueDlg.ui`, `ccPlaneEditDlg.ui`.

**Don't** edit a `.ui` file with the intent of bypassing the Designer — the `uic` tool regenerates `ui_<name>.h` files deterministically. If you need a hand-edited layout, add a custom widget in Designer, then write the custom code in the `.cpp`.

## 3. How to add a new "built-in" menu action to `qCC/` (NOT a plugin)

> **Reminder:** prefer making this a plugin. Use this procedure only if the change can't be a plugin (e.g. it touches dialogs that ship with the main window).

1. **Decide the menu/toolbar placement** — pick an existing menu in `ui_templates/mainWindow.ui` or add a new one.
2. **Add a `QAction` member** to `MainWindow`:
   ```cpp
   // in mainwindow.h, in the Q_OBJECT section's public/private slots
   private slots:
       void doActionMyFeature();

   private:
       QAction* m_actionMyFeature;
   ```
3. **Construct + connect it** in `MainWindow::MainWindow()` (search for `m_UI->setupUi(this);`):
   ```cpp
   m_actionMyFeature = new QAction(tr("My Feature"), this);
   m_actionMyFeature->setObjectName(QStringLiteral("actionMyFeature"));
   // optional: icon, shortcut
   m_UI->menuTools->addAction(m_actionMyFeature);
   connect(m_actionMyFeature, &QAction::triggered, this, &MainWindow::doActionMyFeature);
   ```
4. **Add the slot** in `mainwindow.cpp`:
   ```cpp
   void MainWindow::doActionMyFeature()
   {
       if (!m_app) return;
       // ... open dialog, do work, addToDB, refreshAll
   }
   ```
5. **If you have a dialog**, add `ccMyFeatureDlg.{h,cpp}` + `ui_templates/ccMyFeatureDlg.ui` and link them.
6. **Rebuild** — the `MainWindow.ui`'s generated header (`ui_mainWindow.h`) is regenerated by `qt6_wrap_ui` automatically; you shouldn't edit it.
7. **Verify** — the menu item appears, opens the dialog, runs the slot, updates the db-tree, refreshes the GL view.

> **Tip:** the `MainWindow` constructor is huge (~700 lines). Use the alphabetical `doAction*` list in `mainwindow.h` and the `m_UI->menu...` references in `mainwindow.cpp` to find where similar features are wired.

## 4. Overlay dialogs (`ccOverlayDialog`)

For interactive tools that grab the cursor (clipping box, graphical segmentation, transformation, …), the convention is:

- Inherit from `ccOverlayDialog` (defined in `libs/CCPluginAPI/include/ccOverlayDialog.h`).
- In the plugin/tool constructor, register the dialog with the host:
  ```cpp
  m_app->registerOverlayDialog(this, Qt::TopRightCorner);
  ```
- Freeze the UI while the tool is active (`m_app->freezeUI()` / `m_app->releaseUI()`).
- On tool close, **unregister** the dialog (`m_app->unregisterOverlayDialog(this)` — the host will `deleteLater` it).
- For picking, attach a `ccPickingListener` to the active GL window's `ccPickingHub`.

Built-in examples to copy from:
- `qCC/ccClippingBoxTool.{h,cpp}`
- `qCC/ccGraphicalSegmentationTool.{h,cpp}`
- `qCC/ccGraphicalTransformationTool.{h,cpp}`
- `qCC/ccTracePolylineTool.{h,cpp}`
- `qCC/ccSectionExtractionTool.{h,cpp}`

## 5. The db-tree (left pane)

- `ccDBRoot` (in `qCC/db_tree/`) **is a `ccHObject`** — it owns every loaded entity. The whole loaded scene is a subtree rooted at this node.
- The `QTreeView` is bound to `ccDBRoot` via a `QStandardItemModel` in `MainWindow`.
- The right pane is a **property tree** (`ccPropertiesTreeDelegate`) that switches based on the selected entity type.
- `ccDBRoot` is exposed to plugins via `m_app->db()` (returns the root `ccHObject*`).

**Conventions for selecting / iterating entities from a plugin:**
- `m_app->getSelectedEntities()` returns the current selection.
- `ccHObject::Container` is a typedef for `QVector<ccHObject*>`.
- Check class with `obj->isA(CC_TYPES::POINT_CLOUD)` (bit-mask style) or `ccHObjectCaster::ToPointCloud(obj)` (typed cast).
- Add to the tree with `m_app->addToDB(obj, updateZoom, autoExpandDBTree, checkDimensions)`.
- Refresh GL with `m_app->refreshAll()`.

## 6. The console (bottom pane)

- `ccConsole` (`qCC/ccConsole.{h,cpp}`) is a custom widget that wraps a `QTextEdit`.
- The static methods `ccConsole::Print`, `ccConsole::Warning`, `ccConsole::Error` are used **everywhere** in the codebase as a poor-man's logging (no Qt logging framework).
- From a plugin, use `m_app->dispToConsole(message, level)` where `level` is one of `STD_CONSOLE_MESSAGE`, `WRN_CONSOLE_MESSAGE`, `ERR_CONSOLE_MESSAGE`. Or, the convenience wrapper in `ccStdPluginInterface::dispToConsole(...)` which delegates to the host.

Don't use `qDebug()` / `qWarning()` / `qCritical()` for user-visible messages — they go to stderr, not the in-app console.

## 7. The 3D viewport

- `ccGLWindowInterface` is the public API. The concrete `ccGLWindow` lives inside `qCC_glWindow`.
- `MainWindow` creates one or more `ccGLWindow`s as MDI sub-windows; `m_mdiArea` is the QMdiArea.
- Refreshing: `win->redraw()` (single buffer) or `m_app->refreshAll()` (all viewports).
- Active GL window: `m_app->getActiveGLWindow()` — use this for picking hub attachment.
- Pivots, current camera state, etc. — see `ccGLWindowInterface` and `ccViewportParameters`.

## 8. GL filter plugin integration

- `ccGLPluginInterface::getFilter()` returns a `ccGlFilter*`.
- The plugin is registered into `ccGLFilter::Container` (in `libs/qCC_glWindow`).
- The `ccPluginUIManager::enableGLFilter()` / `disableGLFilter()` slots toggle it on the active GL window.
- The Display menu gets an entry "Apply [filter name]"; a toolbar button is added in the GL filter toolbar.
- `removeFilter()` is wired to the X button in the GL filter toolbar.

For the full lifecycle, read `qCC/pluginManager/ccPluginUIManager.cpp`.

## 9. Color scales

- `ccColorScalesManager::GetUniqueInstance()` (singleton, in `qCC_db`) is the registry of all built-in color scales.
- Plugins can add their own with `ccColorScalesManager::AddScale(customScale)` at startup.
- `ccColorScaleSelector` (in `CCPluginAPI`) is the widget to put in your dialog if the user should pick a color ramp.
- For editing custom scales, use `ccColorScaleEditorDlg` (also `CCPluginAPI`).

## 10. Translations

- Translations live in `<install>/translations/`.
- User-visible strings **must** be wrapped in `tr()` (or `QObject::tr()` for class members).
- `ccTranslationManager` (in `qCC/`) populates the Language menu from the `translations/` directory.
- Plugin-specific translations go in the plugin's `.qrc` under a `i18n` prefix.

---

## 11. Persistent settings (per-user, per-machine)

- `ccPersistentSettings` (in `libs/CCPluginAPI/include/ccPersistentSettings.h`) is a thin `QSettings` wrapper with namespaced keys.
- For plugins: `ccPersistentSettings::PluginSetting("MyKey", defaultValue)` returns the value (or default).
- For `qCC/`: use the bare `QSettings` and the `ccPS::*` constants defined in `ccPersistentSettings.h` (the `PS_` prefix used to be `PersistentSettings_`).

## 12. The "do not do" UI list

- **Don't** open a `QFileDialog` directly from a plugin — use `ccPersistentSettings` to remember the directory and `ccGui::ParamStruct` conventions where applicable.
- **Don't** create raw `QWidget` dialogs in a plugin and forget to set a parent — orphaned dialogs leak. Always pass a parent (use `m_app->getMainWindow()`).
- **Don't** use `qApp->processEvents()` from a long-running action — instead, use `ccProgressDialog` (`libs/qCC_db/include/ccProgressDialog.h`) which integrates with the cancel button + console.
- **Don't** modify `mainwindow.cpp`'s `doAction*` slot ordering — append, don't reorder.
- **Don't** edit a `.ui` file by hand and expect it to round-trip through Designer cleanly.
- **Don't** put a modal dialog inside an `onNewSelection` callback — `onNewSelection` is called from a signal handler and must return promptly.
- **Don't** use `Q_OBJECT` in a class without a corresponding `moc`-compileable parent (CC relies on `AUTOMOC`).
